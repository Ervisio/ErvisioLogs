# ADR 0005: P0 technical baseline

Status: Accepted for P0. Revisit when P1 lands.

| Topic | Choice | Why |
|---|---|---|
| Identifiers | UUID (v7 preferred when generated by the app) in PostgreSQL and ClickHouse | Spec allows UUID or ULID, native types in both stores, one choice for the whole system |
| Go | 1.27, `chi` v5, `pgx` v5, `clickhouse-go` v2, `log/slog` | Small dependency set, stdlib first |
| Migrations | In-repo runner (about 250 lines), embedded SQL, checksums, advisory lock on PostgreSQL | Needs to drive two databases with the same semantics; avoids a heavy dependency. ClickHouse has no locks, so migrations run from one one-shot job |
| Migration preflight | Server never migrates. `/readyz` fails while any migration is pending or edited | Matches "schema migration preflight" in DEPLOYMENT.md |
| PostgreSQL | 17 (alpine), pinned by digest | LTS-class, wide support |
| ClickHouse | 25.8 LTS (alpine), pinned by digest | Native `JSON` type verified by the migration integration test |
| ClickHouse `events` table | Provisional. PARTITION BY day, ORDER BY (workspace, project, stream, timestamp, event_id), no TTL | Real values wait for D004 benchmarks |
| Frontend | React, TypeScript, Vite, Tailwind v4, i18next (en, it) | Per baseline. shadcn components are added when P3 needs them |
| Container | distroless nonroot, read-only root, caps dropped | Secure defaults |
| PostgreSQL TLS inside Compose | Since 0.1.1 the `pg-tls` job writes a self-signed certificate, PostgreSQL runs with `ssl=on`, and the app connects with `verify-full` against that certificate (ADR 0013) | Resolved in 0.1.1 |
