# Ervisio Logs 0.2.0

Version 0.2.0 adds scoped management, a readable event explorer and operator access from the Ervisio plugin. This
checkout prepares the version and source. No release, registry upload or deployment has run as part of this work.

## Changes

- The bundled ClickHouse starts with a low-CPU configuration (`system.*` log tables off, small background pools,
  queries limited to 4 threads). The Compose file now needs Docker Compose 2.23.1 or later. For a standalone
  ClickHouse, apply the snippets in `docs/deploy/standalone.md`. Not measured yet.
- Workspace and project URLs carry their scope. The rail switches workspace and project; settings separate instance
  administration, workspace management, project configuration and the account. Light, Dark and AMOLED themes follow the
  approved blue design.
- Runtime settings show inherited values and environment locks. Manage users, passwords, sessions, invitations,
  stream/environment metadata, ingest limits, quotas, audit history and scoped retention through the app. Instance
  administration grants no workspace membership or access to tenant logs.
- Log v2 adds tags and a project event catalog with titles, message templates, categories, colors and featured fields.
  Actor and target entities use nested attributes. A filter builder, histogram range selection, attribute filtering in
  Live, grouped event details and virtualized rows support investigation.
- Field rules control labels, formatting and presentation. Server redaction replaces configured fields on new events
  before durable ingest. Existing stored events keep their original values.
- Alert setup guides you through the search, threshold and destinations. Channels support webhooks, email and Telegram,
  with delivery history. Instance administrators can subscribe workspace channels to spool-pressure, archive-delay and
  destination-failure alerts when they hold that workspace’s alert permissions.
- Dashboard panels use saved queries for counts, time series and top values. Project usage reports events and bytes by
  time and stream, plus configured quotas and current-process usage.
- Account security offers optional TOTP authenticator codes, single-use recovery codes and WebAuthn passkeys. Manage
  security methods and sessions from Account. Password changes revoke other sessions; administrator password resets
  revoke the target user’s sessions.
- The TypeScript SDK and FiveM resource support tags and actor/target context. The FiveM catalog preset gives project
  owners event titles and templates; player names and identifiers remain opt-in.
- English and Italian in-app guides explain the new workflows with stable topic URLs and server-side examples.

## Ervisio plugin

The 0.2.0 package has nine sections: Overview, Instance, Workspaces, Projects, Users, Archive, Server, Address and
Console. It uses the shared typed `packages/admin-client` and the Ervisio SDK component kit.

Local operator calls use declared admin socket capabilities. The default Docker volume socket is
`/var/lib/docker/volumes/ervisiologs_admin/_data/admin.sock`; standalone uses `/run/ervisio-logs/admin.sock`. For a
different Docker data directory, custom socket path or remote instance, connect over HTTPS with an `evl_adm_` token.
Ervisio requests host approval before the browser makes that connection. First approval reloads the plugin; reconnect
afterwards. The token stays in page memory and calls omit browser cookies.

Server exposes the documented deployment environment with masked secrets and an explicit restart. Console retains up to
20 jobs and 2,000 lines per job for the current page session. Operators can issue ingest tokens; reading and exporting
logs still requires workspace permissions.

## Upgrade preparation

Back up PostgreSQL, ClickHouse and required configuration before applying an upgrade. Preserve
`ERVISIO_LOGS_SECRET_KEY`: the server uses it for token hashes and encrypted security/channel credentials. Apply pending
migrations with `ervisio-logs migrate up` before starting the new binary. This source includes PostgreSQL migrations
through `0012_security_dashboards` and ClickHouse through `0004_tags`. Deploy the server before sending new event fields
from updated SDKs: older ingest decoders reject unknown fields.

Build the release artifacts through the existing release workflow when host validation is complete. The plugin manifest,
package and lockfile are aligned at 0.2.0. Release packaging generates the application bundle and standalone checksums;
this work leaves the development bundle and checksum inputs unchanged.

## Validation and limits

Unit checks, type checking, lint, production builds and browser flows against API fixtures ran during development.
Browser checks covered desktop and mobile management, security flows and Log v2 interactions; passkey checks used a
virtual authenticator.

The local Docker daemon did not respond. Database-backed integration, archive, full-stack smoke and end-to-end tests
could not run in that environment. `scripts/collector-test.py` prepares an isolated stack with a real OpenTelemetry
Collector; it is ready but was not executed in this validation session. The actual Ervisio panel/socket authorization,
remote host approval, physical passkeys, real OAuth providers and in-game FiveM hooks still need host testing. A UI
fixture check does not establish those integrations.

Usage bytes represent uncompressed text payload, not compressed disk or archive size. Daily quota counters live in each
process and reset on restart; multiple replicas do not share their counters. Redaction changes affect newly ingested
events. Retention expiry and manual purge delete data; a purge refuses a range that cuts through an archived segment.
