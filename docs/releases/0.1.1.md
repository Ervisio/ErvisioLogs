> **Not tried on a host.** The changes passed type checks, a plugin build, `go build`, `go vet` and
> `docker compose config`. No stack was started with them and the plugin was not loaded in Ervisio. Try it on a test
> server first.

## Changes

- **Production in Docker**: the bundled PostgreSQL now runs with TLS, and the app checks its certificate
  (`sslmode=verify-full`). A Compose stack with an https public URL starts in production. ADR 0013.
- **Plugin page**: rebuilt on the Ervisio plugin SDK with the look of the other Ervisio plugins. Overview shows the
  route from the internet to the databases, Settings saves with a bar and tells you what blocks production, Console
  keeps the output of each action.
- **Caddy**: the plugin finds the Caddy on the server (system service or container), proposes `logs.<your domain>`,
  writes the site in the plugin-caddy format, validates, reloads and rolls back on failure, then sets the public URL.
  A site you already wrote by hand is recognised and left alone. ADR 0014.
- **Compose**: a new `ervisiologs_edge` network lets a Caddy container reach the app as `ervisio-logs-app:8080`.

## Upgrading from 0.1.0

Upgrade the plugin in Ervisio, then press **Update**. The stack keeps its `.env` and volumes; the `pg-tls` job creates
the certificate on first start. Update changes `POSTGRES_SSLMODE=disable` to `verify-full`. A full
`ERVISIO_LOGS_POSTGRES_DSN` you set yourself stays as it is. The stack stays in development until the public URL is
https.

## Known limits

Same as 0.1.0, plus: the Caddy paths, the Docker socket capability and the upgrade were never run.
