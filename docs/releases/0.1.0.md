First release of Ervisio Logs: self-hosted, multi-tenant log management with a hot ClickHouse tier and Parquet
archives in S3-compatible storage.

> **Pre-release.** Built and checked statically only. The automated tests were written but not run for this release,
> no install was tried on a real host, and the Ervisio plugin was never loaded in Ervisio. Try it on a test server.

## Packages

| File | Use |
|---|---|
| `ervisio-logs-0.1.0-linux-amd64.tar.gz`, `-linux-arm64.tar.gz` | Standalone: binary with the web UI, systemd unit, `install.sh`. You provide PostgreSQL 15+ and ClickHouse 25.8 |
| `ervisio-logs-0.1.0-docker.tar.gz` | Docker Compose bundle: app, PostgreSQL, ClickHouse, migrations, from `ghcr.io/ervisio/ervisio-logs:0.1.0` |
| `ervisio-logs-0.1.0-ervisio-plugin.tar.gz` | Ervisio plugin: installs one of the two above from Ervisio. Unsigned: needs `plugins.allow_unsigned` or developer mode |
| `SHA256SUMS` | Checksums of the packages |

Guides: `docs/deploy/standalone.md`, `docs/deploy/docker.md`, `docs/deploy/ervisio-plugin.md`.

## What it does

- Accounts with a one-time setup code, workspaces, projects, roles, API tokens. Google, Cognito and Discord sign-in
  are implemented but untested against the real providers.
- HTTP ingest (single and batch) with a write-ahead spool, search, live tail and per-project metrics.
- Archives: day segments in Parquet on S3-compatible storage, searched together with the hot tier; retention per
  tenant; local cache with a size budget.
- Saved queries, threshold alerts, signed webhooks (Ervisio, Slack, Discord formats), NDJSON and CSV export.
- TypeScript SDK (`sdk/typescript`) and a FiveM resource (`integrations/fivem`). The FiveM resource was never run in
  game.

## Known limits

- An OTLP/HTTP logs endpoint exists at `/v1/logs` but is **not validated** with a real exporter; do not rely on it.
- Live tail works within one app instance.
- Webhook URLs are stored unencrypted in PostgreSQL.
- No measured capacity figure, no backup and restore drill yet.
- Compose runs in `development` mode by default because its bundled PostgreSQL has no TLS; see the Docker guide for
  production.
