Off-site archive on an SFTP server with a password, such as a Hetzner Storage Box.

> **Not tried on a host.** The changes passed `go build`, `go vet`, type checks, the plugin and web builds and
> `docker compose config`. No SFTP server was reached with them and the plugin was not loaded in Ervisio. Try it on a
> test server first.

## Packages

| File | Use |
|---|---|
| `ervisio-logs-0.1.2-linux-amd64.tar.gz`, `-linux-arm64.tar.gz` | Standalone: binary with the web UI, systemd unit, `install.sh` |
| `ervisio-logs-0.1.2-docker.tar.gz` | Docker Compose bundle, from `ghcr.io/ervisio/ervisio-logs:0.1.2` |
| `ervisio-logs-0.1.2.tar.gz` (+ `.sha256`) | Ervisio plugin, unsigned, in the registry format. Install the signed copy from Plugins › Browse once it is listed |
| `ervisio-logs-0.1.2-ervisio-plugin.tar.gz` | The same plugin under its first name |
| `SHA256SUMS` | Checksums of the packages |

## Changes

- **SFTP with a password**: an SFTP destination can sign in with a password as well as an SSH key ("Sign in with" on
  the Storage page, `"auth": "password"` in the config). The host key pin stays. ADR 0015.
- **Secrets folder**: Compose mounts `./secrets` at `/run/ervisio-logs/secrets` and the systemd unit uses
  `/etc/ervisio-logs/secrets`. Before this, S3 and SFTP destinations could not find their credentials in any install.
- **Plugin**: Settings › Archive credentials saves a password or key into that folder with the right owner and mode,
  and shows only file names.
- Guide: [`docs/deploy/archive-sftp.md`](../deploy/archive-sftp.md), with the Storage Box steps (port 23, host key).

## Upgrading from 0.1.1

Upgrade the plugin in Ervisio, then press **Update**: it creates `secrets/` and recreates the containers. Standalone:
Update runs the new `install.sh`, which creates `/etc/ervisio-logs/secrets` and installs the new unit. Existing
destinations keep working: `auth` defaults to key.

## Known limits

Same as 0.1.1, plus: password sign-in and the plugin's credential commands never ran.
