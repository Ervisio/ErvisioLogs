## Changes

- **Credentials in the Storage page**: when you add an S3 or SFTP destination, type the access key and secret key, the
  password or the private key, or press the file picker to load them from your computer. Ervisio Logs saves them in
  the secrets folder, readable by the service only, and never shows them again. "Use a file already on the server"
  still works and suggests the files already there. ADR 0017.
- **Writable secrets folder**: Compose mounts `secrets/` read-write; the standalone folder becomes
  `root:ervisio-logs 2770` and the systemd unit allows writes to it.
- New API: `GET /api/v1/admin/storage/secrets` (names only) and `PUT /api/v1/admin/storage/secrets/{name}`.

## Upgrading from 0.1.3

- **Plugin**: upgrade it in Ervisio and press **Update**. On a standalone install, Update runs the new `install.sh`,
  which sets the folder mode and installs the new unit. On Docker it brings the new `compose.yaml`.
- **Standalone by hand**: run the new `install.sh`; it sets the folder mode and installs the new unit.
- **Docker by hand**: take the new `compose.yaml` from the bundle and run `docker compose up -d`.

No database migration.

## Known limits

Same as 0.1.3. A secrets folder outside `/etc/ervisio-logs/secrets` on a standalone install stays read-only unless
you add it to `ReadWritePaths` in the unit.
