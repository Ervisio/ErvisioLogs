# integrations
Purpose: two clients of the platform: FiveM Lua resource that forwards game-server logs to ingest, and an Ervisio (server-panel) plugin that installs/operates Ervisio Logs.
Entry points: integrations/fivem/ervisio_logs/{fxmanifest.lua,config.lua,server/main.lua,server/queue.lua,server/redact.lua}; integrations/ervisio-plugin/{src/index.ts:activate,src/api/logs.ts,src/api/caddy.ts,src/api/caddy-core.ts,src/api/docker.ts,plugin/manifest.json,plugin/bin/standalone.sh}.

## FiveM (server-only resource, v0.1.0)
Flow: exports `Log(stream,level,event,message,attrs)` / `LogBatch(events)` / `GetStats()` (main.lua) -> Queue:log -> _build (redact.lua key/message scrub, truncation per config.limits, stream picked by prefix table `streams`, else default_stream) -> in-memory queue -> tick loop (250ms) -> _take_batch -> PerformHttpRequest POST {url}/api/v1/ingest/batch, Bearer token -> _on_response.
Settings: convars win over config.lua: `ervisio_logs_url`, `ervisio_logs_token` (required, set in server.cfg), `ervisio_logs_environment`, `ervisio_logs_host` (fallback sv_hostname). Console cmd `ervisio_logs_resume` re-reads token after auth stop.
Response handling (queue.lua:_on_response): 200/202 ok | 401/403 clear queue + disable sending (needs `logs:ingest` scope) | 413 split/drop | 429/503 honour Retry-After (cap 300s) | 0/408/5xx backoff base*2^(n-1) cap 60s, max_attempts 6 | other 4xx drop batch, no retry.
Invariants:
- Token never leaves server: `server_only 'yes'`, no client/shared scripts, no `files`; playerJoining/Dropped use plain AddEventHandler (not RegisterNetEvent) so clients cannot trigger them.
- Privacy opt-in: player_name, identifiers (license/discord/steam), IP all default false; redact keys (password, token, iban...) masked as [REDACTED].
- Queue caps: max_queue 5000 (oldest dropped), batch 200 events / 800000 bytes (< server 1 MiB), attr depth 6 (<API 8).
- Wire format identical to the TS SDK; keep in sync with backend ingest limits.
Gotchas: tests are pure Lua (tests/queue_spec.lua) with injected deps (now, json_encode, http), not run by `make test`/CI; run manually with lua. fxmanifest version is hand-bumped, independent of platform.

## Ervisio plugin (id `ervisio-logs`, version tracks the platform release, 0.1.5)
Purpose: inside the Ervisio panel, install Ervisio Logs as Docker Compose stack (/opt/stacks/ervisio-logs, project `ervisio-logs`) or systemd service (standalone), edit its env, and publish it through Caddy.
Flow: activate(sdk) registers page `logs` (views/LogsPage.tsx: Setup/Overview/Settings/Address/Console/Secrets). Every host action is a command declared in plugin/manifest.json `capabilities.commands` (argv templates, `admin`, `adminUnlessGroup`, arg regex patterns); api/*.ts can only call those. Mode stored in ~/.config/ervisio/plugins/ervisio-logs/settings.json.
- Compose: BUNDLE (src/bundle.generated.ts: compose.yaml + .env.example embedded at release) is written to the stack dir; env generated via api/env.ts:randomSecret.
- Standalone: bin/standalone.sh downloads GitHub release tarball matching bin/release.version, verifies sha256 from bin/release.sha256, runs its install.sh.
- Caddy: caddy-core.ts parses Caddyfile (tokenize/scan), manages a marked block (MARKER) or own file `ervisio-logs.caddy`, caddy.ts validates (`caddy validate`) then reloads; Docker Caddy joins network `ervisiologs_edge` to reach container `ervisio-logs-app`.
- Secrets view: archive credentials written via `secrets-install` (0400 uid 65532 for Docker; /etc/ervisio-logs/secrets for standalone) - never listed by content.
Invariants:
- manifest.json and package.json versions MUST equal the release version (release.sh and release.yml fail otherwise).
- bundle.generated.ts is generated by scripts/release.sh; committed version is a dev placeholder ("0.0.0-dev" => `isRelease` false => install disabled). Do not hand-edit.
- Docker API access limited to manifest `http.rules` regexes; added Docker/Caddy calls need a matching manifest entry.
- No manifest.sig shipped; the Ervisio/plugins registry signs it.
- ENV is never forced to development (warnProduction warns instead); unpassedKeys warns about ERVISIO_LOGS_* keys in .env not referenced by compose.yaml (computed from the file at runtime); secrets created by ensureSecrets.
- Can talk to the API only via the admin unix socket (ADR 0019, volume ervisiologs_admin); not wired in the plugin yet.
Gotchas: `npm test` = node --test test/*.test.ts. envSet writes values unquoted. @ervisio/plugin-sdk is a git dep (github:Ervisio/plugin-sdk#v0.3.0); CI rewrites ssh->https for it. Build = `tsc --noEmit && vite build && ervisio-plugin-pack copy` (cd integrations/ervisio-plugin). minCore 0.5.0.
